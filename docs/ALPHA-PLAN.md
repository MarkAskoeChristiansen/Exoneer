# Alpha plan – from prototype to alpha, ending at world authoring

Status: execution brief, revision 2, 2026-09-03 (after a three-lens design review). Parent: [ROADMAP.md](ROADMAP.md). Rules: [GAME-SCOPE.md](GAME-SCOPE.md) section 10, [VISION.md](VISION.md).

## 1. What alpha means here

Alpha is reached when a crew can play the full sandbox loop in survival mode on a test world, every 1.0 maintenance class exists at reduced order, and all three optional projects can succeed and fail on physical readings. World content is the only remaining work, and the owner authors the first basin in the editor using a written guide.

## 2. Ground rules for every change

- Server authority. Readings live in `FPartCondition` (replicated and saved on pieces and blocks). New per-frame writers use a deadband before marking dirty, as `UWheelModule::ConsumeTelemetry` does. `AExoneerGameState` arrays are plain replicated arrays: write them only on change.
- Physics thread touches no UObject. Anything the Chaos sim callback needs is baked into the plain `Config`/`Command` structs in `BuildSimInput`.
- Readings in SI or published engineering units. No percentages on the visor or wrist (this includes the two existing vitals lines). No stored 0-1 durability bar; the two dimensionless readings that exist are named for what they are: dust opacity and capacity fade, both shown to the player as the derived physical quantity (watts, kJ). Terminal states derive from readings. A stored flag is allowed only where hysteresis needs one (thermal cutout).
- Repair verbs match failure: wipe (dust), patch (seal, worse each time), replace (terminal part, consumes a fabricated spare), rebuild (structure). Never weld-to-heal.
- Sandbox first. Nothing gates a tool, recipe or piece behind a project. Handshake changes what the crew knows, not what the world does.
- Bootstrap (`scripts/BootstrapPrototype.py`) stays idempotent and authors every new item, recipe, piece, block, physical material, map fixture and project definition. New level actors go through the label-keyed `ensure_actor` pass that runs on every bootstrap, never the create-once branch. UE 5.8 Python gotchas: bool properties drop the `b` prefix, `FGameplayTag` goes through `UExoneerBootstrapLibrary`, IMC bindings use `map_key`, MIC parent via `MaterialEditingLibrary`.
- Every criterion, capacity, deadline and conversion that could silently pass gets a pinned test (see section 4).
- Every step ends with `Build.bat` green and every automation suite green. New pure math gets a test in `Source/Exoneer/Tests/`.
- Docs: en dash, no em dash, sentence-case headings.
- `g` is the biome gravity: `GravityMps2 = FMath::Abs(Biome->GravityZ) / 100` (biome authors uu/s^2, `-980`). Never a 9.81 literal.

### Step 2 – motor thermal: derate, cutout, readout

Physics (all in `ExoneerMaintenance.h` as pure functions with tests):
- Heat input is loss only, never shaft work: `P_loss = CopperLossW + (1 - Efficiency) * |MechanicalW| + ControllerIdleDrawW`. `WheelSimStep.cpp` already computes these terms; marshal `LossPowerW` back as a new `FWheelSimTelemetry` field next to `ElectricalPowerW`.
- Copper-loss basis stays the derated `Config.StallTorqueNm` (the ratio `T/T_s` is derate-invariant, so a stalled motor keeps burning its full `CopperLossAtStallW`). Do not add a rated-torque denominator. Test: at full throttle stall, `LossPowerW` does not fall when the derate scale falls.
- `FVehicleWheelSpec` (Drive) gains `DerateOnsetTempC = 120`, `TripTempC = 150`, `CutoutClearTempC = 110`, `ThermalMassJPerC = 800`, `CoolingWPerC = 28`.
- `WindingTempStep(TempC, LossW, AmbientC, CoolingWPerC, ThermalMassJPerC, Dt)` = `TempC + (LossW - CoolingWPerC * (TempC - AmbientC)) * Dt / ThermalMassJPerC`. Equilibria to state in the test: full stall at `CopperLossAtStallW 5000`, ambient 20 C: `20 + 5000 / 28 = 199 C` (above trip, so the cutout is reachable); cruise at 100 Nm, 20 rad/s, efficiency 0.85: copper `5000 * (100/300)^2 = 556 W`, friction `2000 * 0.15 = 300 W`, total about 860 W, equilibrium about 51 C (below onset). Remove the hardcoded 20 C floor and the 180 C ceiling; clamp to `[AmbientC - 5, TripTempC + 60]`.
- `ThermalDerateScale(TempC, OnsetC, TripC)` = 1 below onset, linear to 0.35 at trip, 0.35 above. Not to zero: the cutout handles zero.
- Cutout with hysteresis: `FPartCondition` gains `uint8 bThermalCutout : 1`. Set when `WindingTempC >= TripTempC`, cleared when `WindingTempC <= CutoutClearTempC`. While set, `Config.StallTorqueNm = 0` (the motor freewheels; `MotorTorque` returns 0 for a zero stall torque, `MotorElectricalPower` guards its denominator). Replicated with the record as today; save needs nothing new (whole-struct copy).
- `BuildSimInput`: `Config.StallTorqueNm = (Spec->bDriven && !Rec->Condition.bThermalCutout ? Spec->MaxMotorTorqueNm : 0.f) * ThermalDerateScale(...)`. Keep the `bDriven` gate.
- `ConsumeTelemetry`: ambient from `Owner->GetEnvironmentManager()->GetCurrentAmbientTemperatureC()` (fallback 20 C). Deadband 1 C before marking the record dirty, as tread does.
- Readout: `FVehicleDrivetrainSummary.MaxWindingTempC` and `bAnyThermalCutout`; `AVehicleConstruct::GetMaxWindingTempC()` scanning Complete wheel records (copy `GetMinTreadDepthMm`). HUD pilot panel line `MOTOR %.0f C`, `VisorWarn` above onset, text `MOTOR CUTOUT` while any wheel is cut out. Smooth like `SmoothedSlip`.
- Terminal state at alpha: cutout, torque 0, recovers by cooling. A motor whose winding is scrap (replace verb) is post-alpha and A2 says so.

### Step 3 – live load, deflection, decks (V-SPAN) and the grounded-deployable fix

Load path:
- `UPieceDefinitionDataAsset` gains `LoadCapacityKg` and `TerminalDeflectionMm = 60`. Author every piece (section 3 table below); the code treats `LoadCapacityKg <= 0` as "collapses under any wheel" by branching before any division.
- `UWheelModule::TickModule` keeps `TWeakObjectPtr<ABasePiece> GroundPiece` from the probe hit (game thread only, weak so a collapsing piece reads null). `ConsumeTelemetry` (server) calls `GroundPiece->ReportLiveLoad(Telemetry.NormalLoadN)` when the piece is valid and Complete.
- Ghosts carry no load: `ABasePiece::RefreshVisualState` Ghost branch also sets `SetCollisionResponseToChannel(ECC_WheelProbe, ECR_Ignore)`, and `ReportLiveLoad` early-returns unless the piece is Complete. Update `docs/design/wheels/design-engine-arch.md` line 228 to match.
- `ABasePiece`: transient, non-replicated `PendingLoadN` (sum over all wheel reports since the last read) and `PendingLoadFrames`. `ReportLiveLoad` adds to both and arms the owning structure's 5 Hz load timer (`ABaseStructure::ArmLoadTimer`, idempotent, re-armed on every call so a structure merge under a parked rover keeps servicing).
- `ABaseStructure` load timer (5 Hz, self-disarms after 1 s with no reports): per piece with `PendingLoadFrames > 0`: `LoadN = PendingLoadN / PendingLoadFrames` (mean of the per-frame sum), then zero both. `Ratio = LoadN / (LoadCapacityKg * GravityMps2)`. If the piece is condemned (see below) or `LoadCapacityKg <= 0`, `Ratio = 2`. If `Ratio >= 2`: gross overload, immediate event: mark the piece overloaded and call `RecomputeSupport`, which treats an overloaded piece as `SupportValue 0` and does not exempt it through the grounded branch; the existing 0.5 s collapse batch does the rest. If `1 < Ratio < 2`: `Condition.DeflectionMm += 6 * (Ratio - 1) * dt` mm (permanent set, one-way, no elastic recovery; 1.5x rating reaches 60 mm in 20 s). Deadband 0.5 mm before marking dirty.
- Condemned deck: `DeflectionMm >= TerminalDeflectionMm` sets effective capacity to 0 (the piece stays standing, keeps `SupportValue`, carries nothing). The legal verb is rebuild: deconstruct and weld a new piece. Any further wheel load on a condemned piece is a gross overload and collapses it.
- Capacities (kg), sized to the test rover (about 3.0 t on six wheels, 4.9 kN per wheel, one axle about 9.8 kN): foundation 5000, floor 800, ramp 1000, beam 1500, road_deck 1200, road_deck_light 600 (new piece, cost plate 1 + stone 2), bridge_span 1500 (new piece, below), wall 400, roof 300, storm_shelter 800, radio_mast 200, dish_array 400, refinery 800, fabricator 800, oxygen_generator 800, battery 600, solar 200, launch_pad 50000 (step 7b). Every piece is authored; none is left at the 0 default. Expected: one axle on `road_deck_light` gives `Ratio 1.67`, terminal in about 15 s; on `road_deck` gives `Ratio 0.83`.
- The overload and deflection rules apply only to pieces that reported live load this window; a machine face is never judged by a deck rule.
- New piece `bridge_span`, sized to the existing 2 m socket module and chained: mount tag `M_FLOOR` so it snaps to a beam `Top`; not groundable; its own sockets `Edge_E` at (100, 0, 0) and `Edge_W` at (-100, 0, 0), both accepting `M_FLOOR`, so spans chain end to end; `SupportBudget 6`, `SupportCost 1`; cost iron_ingot 3 + plate 2 + stone 4. Support relaxes from a grounded beam (8, then 7, 5, 4, 3, 2, 1), so up to seven spans reach from one anchor. A two-anchor solver stays post-alpha; the single-parent tree is unchanged.
- Quick bar split, done here because this step grows the list: `B` cycles pieces only, `N` (new input action, bootstrap `map_key`) cycles vehicle blocks only. `road_deck_light` and `bridge_span` are appended to the pieces list.
- Test: pin the denominator (`5000 kg` at `9.8 m/s^2` is `49 kN`) and the mean-of-frames read, and that a ghost piece never accumulates deflection.
- Grounded deployable fix (existing bug the dish will hit): a deployable placed on terrain with no parent founds a structure and is then destroyed 0.5 s later as an orphan (`BaseStructure.cpp:509-520` orphan rule, `:456-462` seeds only `bGroundable`). Fix in `RecomputeSupport` with the same predicate the build tool uses for terrain placement: seed `(Def->bGroundable || Def->MountTag == ExoneerTags::Mount_Deployable) && !ParentPiece && Complete` with the piece's own `SupportBudget`, and use the same predicate in the collapse-loop exemption. One predicate, two places. Test with the transient-world fixture from step 1 if cheap, else document the PIE check.
- Focused-piece panel (new surface, wrist role): `AExoneerHUD::DrawFocusedPiecePanel` draws when the focused actor is a Complete `ABasePiece`: `PIECE <id>`, `LOAD %.0f kg / CAP %.0f kg` (last read load; only for rated pieces), `DEFLECT %.1f mm`, `DUST` as delivered fraction of nominal watts for solar and radio faces (`%.0f W of %.0f W`), `HEALTH`. Later steps add lines here. The machine recipe panel keeps its place below it.
- Bootstrap: capacities above, `road_deck_light`, `bridge_span` with its sockets, the `N` input action, the split quick bar. Update `docs/design/wheels/design-engine-arch.md` line 228 (ghost transparency) to match the code.

### Step 4 – battery fade and machine replace

- `CapacityFadeDelta(ThroughputJ, TempC)` in `ExoneerMaintenance.h`: fade per joule cycled, `k = 1 / (400 * RatedJ)` scaled by `1 + 0.05 * max(0, TempC - 35)`. Floor: fade never exceeds 0.6 (usable capacity never below 40 percent of rated). Test: monotone in throughput and temperature, floor holds.
- Vehicle writer: the `SetBatteryCharge` lambda in `AVehicleConstruct`'s power tick already has old and new charge; accumulate `|delta| * EffectiveCapacityJ` as throughput and apply `CapacityFadeDelta` to `Record.Condition.CapacityFade01`, deadband 0.005 before marking dirty. `StateScalar` is the fraction of effective capacity; every ledger read of `Def->EnergyStorage` for a battery block becomes `EffectiveCapacityJ = EnergyStorage * (1 - CapacityFade01)`. Throughput on a multi-battery construct splits proportionally to effective capacity (the ledger already charges proportionally).
- Structure writer: `UPowerNetworkComponent::Simulate` moves energy into and out of each battery node's `StoredEnergy`; accumulate `|dStoredEnergy|` per node and call the same function with the environment ambient temperature. `AMachinePiece::ApplyDefinitionStats` sets `Power->StorageCapacity = Def->EnergyStorage * (1 - Condition.CapacityFade01)` and is re-applied when fade changes past the deadband. `USaveGameSubsystem::RestorePieceState` assigns `Condition` before re-applying stats, then clamps `StoredEnergy`.
- Replace for pieces: `UPieceDefinitionDataAsset.SpareItemId`; `ABasePiece::ReplacePart(UInventoryComponent*)` consumes one spare, calls the new `ResetConditionToNominal()` (`Condition = FPartCondition()` then machine-specific nominal values), keeps placement, returns true. `UBuildToolComponent` re-press branch for `ABasePiece`: check the terminal reading first (`CapacityFade01 >= 0.6` on a piece with `EnergyStorage > 0`), call `ReplacePart`; otherwise fall through to `WipeDust` as today. Dust never triggers Replace: wipe clears dust fully and that is the only dust verb.
- Vehicle `ReplacePartAt` widens past `bIsWheel` to any block whose definition sets `SpareItemId` and whose reading is terminal (tire gone, or fade at floor); the `tire` fallback stays for wheels.
- Bootstrap: item `battery_cell` (fabricator: plate 1 + silicon_wafer 1 + carbon 2, 5 s, 200 W); `SpareItemId battery_cell` on the battery piece and battery block; `SpareItemId tire` set explicitly on all eight wheel blocks. Focused-piece panel gains `BATT %.0f kJ of %.0f kJ` (stored of effective) for pieces with storage.

### Step 7 – Handshake and Road to Orbit (two passes: 7a, 7b)

7a Handshake:
- `ADishPiece : AMachinePiece` for `dish_array` (bootstrap sets `piece_class` to it; an existing dish keeps the old class until rebuilt). Replicated `AzimuthDeg`: an absolute world azimuth on a 15 degree lattice starting at 0, not an offset from the placement yaw (which snaps in 90 degree steps), so boresight is exactly reachable. Derived `SignalDbm` (server computed, replicated with a 1 dB deadband). E slews `+15` (prompt "Slew dish +15"). Save: `FSavedBasePiece.AzimuthDeg`, captured and restored with `Condition`.
- Link budget (pure function in `ExoneerMaintenance.h`): `SignalDbm = 43 + GainDb(Err) - 130 - 12 * StormIntensity - 6 * SurfaceOpacity01 + 10 * log10(max(SupplyFraction, 0.01))`, with `GainDb(Err) = max(-12 * (Err / 12)^2, -18) - 0.06 * Err` (12 degree half-power beamwidth, -18 dB sidelobe floor, a shallow taper so no two lattice positions read the same and hill-climbing works from anywhere). Criterion target -95 dBm. Check the numbers in the test: boresight, clear sky, full supply reads -87 (8 dB margin); one lattice step off reads about -106 and fails; a full storm on boresight reads -99 and fails; supply below about 0.2 fails; a fully dusted dish at boresight reads -93 and still passes, dust plus a light storm fails. Outside the window the relay is below the horizon: `SignalDbm = -120` and the readout says `NO CARRIER`. Test: strictly monotone in error over 0-180, and for every seed a lattice azimuth reaches error 0.
- Actuator wear: `FPartCondition` gains `ActuatorBacklashDeg`. Storm exposure grows it by `0.02 * Intensity` deg per second. During storms the azimuth drifts `Intensity * (0.3 + Backlash / 10) * 2` deg per second with random sign, snapped back to the lattice when the storm ends. Verb: replace actuator (spare `actuator`, fabricator: motor 1 + plate 1), via the piece Replace path from step 4 with terminal `Backlash >= 5`. Dust on the dish is wiped as on solar.
- `FOrbitalKnowledge` gains `RelayAzimuthDeg` (-1 until seeded), `bRelayAzimuthKnown`, `WindowStartTimeOfDay01`, `WindowLength01 = 0.15`, `PadSlopeLimitDeg = 6` (always the true value; Handshake reveals it), `MaxAscentAltitudeM`, `bAscentAchieved`. Delete `NextWindowTimeOfDay01`; the HUD line derives the next window from start and length. `UProjectSubsystem::Initialize` seeds `RelayAzimuthDeg = 15 * RandRange(0, 23)` and `WindowStartTimeOfDay01` on a fresh world (random stream from the save seed or the world name) when unseeded. Window wrap: `InWindow = Frac(Tod - Start) < Length`.
- Project definition: `UProjectDefinitionDataAsset` gains `DeadlineSols` (0 = no deadline) next to `DurationSols` (hold). `FProjectCriterion` gains `HoldSeconds`. `FProjectRuntime` gains `TArray<FProjectCriterionSnapshot> { Measured, Target, bPass, HeldSeconds }`, written every evaluation, replicated only when `bPass` flips or `Measured` moves past 5 percent; `HeldSeconds` replicated as whole seconds.
